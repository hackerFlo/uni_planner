### Expired open tasks

The expiry boundary is the previous Monday at the start of the account's local calendar week, not the week currently selected in the website. Tasks assigned exactly on that Monday remain. Future assignments beyond the sidebar's next-week window stay stored and can still be read through MCP. Completed, archived and unassigned tasks are never removed by this maintenance.

Website week selection, assignment dates and today highlighting use the same saved `notify_tz` account timezone as server maintenance, including when the browser's device timezone differs. Authenticated user responses expose that owned timezone. The account clock updates at its actual midnight, on visibility return and through a safety poll; changing accounts or the saved timezone recalculates the displayed date immediately. Notification-setting saves and planner revision refreshes refresh the user clock data.

An isolated rendered smoke check exercised the actual `TimeProvider`, sidebar filtering and task card at `2026-10-25T23:30Z` with the process timezone set to America/Los_Angeles. A Berlin account displayed October 26 and excluded the expired October 12 assignment; a Los Angeles account displayed October 25 and retained it. The check also confirmed reachable-card dimming, Unassign and backlog visibility using synthetic providers. This is a local render check, not browser interaction or Tunnel/Access evidence.

`get_planner_context` reports `planningWindow` and `taskRetention.expiresBefore` without performing cleanup. Explicit materialization reports `expiredTaskCount`; the count includes old recurrence rule carriers that were replaced by a retained occurrence.

Recurring series are materialized before cleanup. When an expired open task carries a recurrence rule, the earliest owned retained occurrence matching the original cadence becomes the rule carrier, including older completed or archived occurrences. Retained siblings are reparented without changing their dates, contents, completion or archive state. Keeping the chronological rule carrier preserves later recurrence edits to retained history. Missing replacement occurrences cause a rollback instead of silently ending the series. Later recurrence materialization does not recreate deleted expired dates.

Automatic cleanup has no undo entry and changes the account planner revision, which can invalidate an older edit draft, cursor or undo operation. Explicit MCP materialization can delete expired tasks even if its requested result filters do not include those tasks. It requires enabled planner writes and a live write grant; stored-only task/week reads never perform cleanup. Changed descriptions and destructive tool annotations require a client discovery refresh after upgrading. Real Tunnel/Access verification, authorization expiry through that path and client confirmation behavior remain outstanding.

The scheduler uses the same per-account materialization/cleanup service and catches up on its next minute tick after startup or downtime. Successful maintenance runs at most once per account-local day in that process; a failed account is retried on the next tick without preventing other accounts from being maintained. Website planner loading also runs the shared maintenance.

### Task activity markers

The task-card marker records the latest qualifying MCP action: creating a task (including a copy) uses `agent_activity_action: "created"`; changing its assigned date, including assignment or unassignment, uses `"moved"`. `agent_activity_at` is the server-recorded UTC timestamp. These fields are server-managed, not accepted as task-write inputs. They identify activity through MCP; they do not establish whether a human prompted or approved the client action.

Other MCP edits and same-date moves do not create a new marker. Website task edits clear the affected card's marker; incidental renumbering of neighboring cards does not change their markers. Clicking the card icon dismisses its marker persistently. MCP clients use `dismiss_task_agent_activity` with the owned task ID and ordinary mutation controls. Hover/focus text describes the action and its relative calendar day and local time. This is a latest-action indicator, not a complete activity history.

Refresh client tool discovery after upgrading so the dismissal tool is available. The new feature is not covered by the historical test totals below until its verification results are recorded.

## Remaining verification and limits

- **Cloudflare/client gate partially exercised:** ChatGPT web OAuth, refreshed tool discovery and one planner-context read passed on the inspected deployment. Fresh email-code login, refresh/expiry/provider revocation, restart, stable identities across two real isolated accounts and full feature equivalence remain unverified. This review's local fixes have not been deployed.
- Claude desktop and iOS, native ChatGPT desktop and standalone ChatGPT iOS remain unverified. Standalone iOS availability is unconfirmed; web support must not be used as evidence of it.
- The built client image now has an actual entrypoint/nginx syntax and HTTP smoke harness (`scripts/smoke-client-container.sh`), covering default/configured/maximum-length hosts, invalid-host rejection, website/MCP path isolation, inherited security/cache headers and synthetic upstream forwarding with explicit website ports, backend DNS absence and backend replacement recovery. The publication workflow runs it before either image push and waits for reusable CI test/build/lint/production-audit checks. Target NAS architecture/native modules, real Tunnel/Access, MCP Inspector, proxy-hop/limiter load behavior and rollback drill remain pending. Structural/shell tests are supplementary.
- Notification delivery is inherently ambiguous on SMTP timeout. Retained retries never resend automatically; email cannot be undone. Unattended execution depends on client behavior, permissions and grant lifetime.
- Preferences, notification settings, bulk quote restoration/import, email sends, export preparation and automatic expired-task cleanup do not offer undo. Large planner changes may exceed recovery bounds; receipts explicitly report when undo is unavailable. An unrelated subsequent edit/materialization can invalidate undo because concurrency is account-wide.
- Legacy unversioned website compatibility is allowed only while agent writes are off. Old partial board endpoints reject requests when agent writes are enabled. Remove compatibility in a reviewed release after old browser bundles are retired.
- Browser automation now exercised the installed ChatGPT plugin and website connection status; full planner interaction and the remaining cross-feature parity/security review are still outstanding. The server write flag was initially off despite all account grants; after the operator applied the configuration by rebuilding/recreating the deployment, the website no longer reported writes disabled and ChatGPT refreshed to include editing tools. No live mutation was tested.
- Body/result ceilings do not bound all intermediate work: list fingerprints scan the account collection and exports build the full snapshot before the 5 MiB check. Process-local rate-limit counters reset on restart. Retention/cleanup and further account-size/load limits are detailed in the [security record](mcp-security.md).
